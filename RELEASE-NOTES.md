DiceMaster v0.5.1 adds persistent WebSocket room updates and bounded network recovery. The relay requires protocol 2, supplied by v0.5.1; older standard clients are rejected with an update-required response before Durable Object storage is accessed. The new client displays "Please update DiceMaster to the latest version." when rejected and stops requests until updated/reloaded. This protocol gate is compatibility protection, not authentication: all participant and GM authorization checks remain mandatory.

Safeguards: five connection attempts per rolling ten minutes, followed by a five-minute cooldown and explicit Resume; server errors or HTTP 429 pause requests immediately for at least a minute (respecting Retry-After); three transport failures also pause. Merely waiting does not resume requests. Manual actions are limited to one per second, table browsing to once per ten seconds, and all HTTP/handshake attempts share a 60/minute client budget. Short-lived successful sockets do not erase the reconnect budget. Budgets are local to the plugin lifetime, not an account-wide quota guarantee.

Operator emergency switch: set the Worker variable RELAY_PAUSED to the string true. Requests from supported clients then receive 503 / Retry-After 300 before storage access. Remove the variable or set false to restore access. Incoming requests still count at Cloudflare; old or modified clients cannot be prevented from sending traffic by application code. Players must update or disable obsolete versions. Do not claim these safeguards protect against arbitrary traffic or guarantee no account limit can be reached.

Connections stay open while at a table. Rolls and roster changes are pushed; user actions and private GM operations use authorized HTTPS requests. Initial connection/reconnection includes one catch-up request. Protocol health checks remain; no ongoing application polling is performed by updated clients. A shared cleanup alarm remains server-side. Modifiers never enter public socket payloads.

Validation: zero-warning Release build, 20 relay/security/storage tests, and standalone C# budget tests pass. The simulated 100-client HTTP-503 outage sends 100 initial requests and zero automatic retries thereafter. This is a deterministic budget simulation, not a live Cloudflare load test. The local Cloudflare runtime cannot start in this sandbox. The updater requires a live WebSocket check before publishing. No live deployment or new load test was run against the unavailable account.

Deploy using the existing Update-And-Publish-DiceMaster.ps1 after the hosting issue is resolved. The relay changes first, temporarily rejecting old clients until the release is published and players update. The script preserves the GitHub README and stored GM credentials.
